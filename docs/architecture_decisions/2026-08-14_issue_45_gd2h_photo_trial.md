## 1. 目标与边界

本轮只完成官网目录普查、护理栏目排除、10 位临床/医技医生试采和本人职业照审计材料，不写入统一总底表，不生成正式 Obsidian 画像，不进入 FULL。

固定边界：

1. 只使用 `gd2h.com` 官网公开目录、详情页和官方图片路径。
2. 详情只接受 `/site/detail/<ID>.html`；数字与 hash ID 均按官网原样保留，大小写敏感，不归一、不截断。
3. 琶洲、民航两院区是同一静态 HTML 内的前端显隐标签，不构造独立院区 URL。
4. 护理专家整栏排除，并保留逐 ID、栏目和个体护理职称证据。
5. 照片只接受医生本人职业照；默认占位图和空 `src` 只计数，不作为照片样本。
6. 图片请求只增加与该图片对应的同域公开详情页 `Referer`。管理员授权：首次非 200 后等待 1 秒，以同一 URL、同一 Referer、同一请求头仅重试 1 次；不注入 Cookie，不改变请求头，不绕过验证；第二次仍失败立即终止整次 TRIAL。

## 3. 实现决策

新增专用适配器 `gd2h_static_campus_expert_photo`：

1. 精确识别唯一授权目录 URL，并对 608 个详情 ID 执行格式、唯一性和大小写原样对账。
2. 解析同页 `.xxk-item1/.xxk-item2` 两院区和 `.zjlist0/.zjlist1/.zjlist2` 三栏目，固定校验六栏计数。
3. 护理整栏排除后，逐一读取 581 个临床/医技详情；TRIAL 只从姓名一致、身份非护理、本人职业照可得的候选中选 10 人。
4. 样本强制覆盖两院区、临床/医技两类、数字/hash 两种 ID 和至少 3 个科室。
5. 详情正文只对开头的 GD2H 专用面包屑做锚定清洗；正文其他位置出现相似文字时保留，避免扩大删除范围。
6. 排班标题命中后清除其尾段；患者案例、导航、排名/评价和私用区字符继续执行写出前扫描。
7. 照片文件名固定为 `姓名-科室-主职称-医院.<魔数扩展名>`；主职称采用最长非重叠匹配，防止把“副主任医师”降格为“主任医师”。
8. 图片字节保持官网原图，不压缩；记录 URL、详情 Referer、字节数、SHA-256、魔数、宽高和重试次数。
9. 唯一重试后仍失败的图片异常不再降级成行级提示，而是立即抛出 `GD2H 图片下载熔断`，终止整次 TRIAL。
10. 新增 `work/tests/test_gd2h_photo_trial.py`，覆盖严格 URL/ID、六栏目、护理排除、面包屑和排班清洗、主职称、同请求唯一重试、试采覆盖、固定普查门禁与 FULL 熔断。

## 7. 阻塞、根因、解决与防复发

### 7.1 图片直接请求 403

- 阻塞：官网图片直接 GET 返回 403。
- 根因：官网图片启用了基于公开详情页来源的防盗链校验。
- 解决：只携带完全匹配的同域公开详情页 `Referer`；未加入 Cookie、登录、验证码或挑战求解。
- 防复发：下载前校验 Referer 的详情 ID 与图片所属样本 ID 一致；请求策略写入 payload 并由测试固定。

### 7.2 正文开头残留面包屑

- 阻塞：详情正文出现 `首页 > 患者服务 专家介绍...` 导航片段。
- 根因：官网把面包屑拆成多个相邻段落，通用清洗无法稳定识别。
- 解决：新增只锚定正文开头、只匹配 GD2H 专家页固定结构的专用面包屑清洗。
- 防复发：专项测试同时验证开头面包屑被移除、正文中相似文字不被误删；写出门禁扫描导航残留。

### 7.3 唯一重试后的失败仍被采集循环降级

- 阻塞：下载函数能在第二次非 200 时抛错，但上层采集循环会捕获后继续其他照片，不符合“仍失败立即熔断”。
- 根因：早期照片采集沿用了行级失败留痕策略。
- 解决：GD2H 专用循环改为重新抛出带姓名和详情 ID 的熔断错误，立即终止整次 TRIAL。
- 防复发：专项测试固定同 URL、同 Referer、同请求头恰好两次调用和一次 1 秒等待；任何第二次非 200 必须抛错。

### 7.4 副主任医师文件名被降格

- 阻塞：文件名主职称曾把“副主任医师”截为“主任医师”。
- 根因：短词优先/子串匹配没有保证最长非重叠职称。
- 解决：新增 `gd2h_primary_title()`，采用最长非重叠职称匹配，并安全修正三张文件名。
- 防复发：写出门禁逐项对账姓名、科室、主职称、医院和扩展名；专项测试固定副主任/主任区分。
