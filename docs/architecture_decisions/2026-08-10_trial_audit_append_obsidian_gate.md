# 2026-08-10 试采审计与追加画像门禁调整

## 背景

管理员补充要求：

1. Codex 提示词中，Claude 审计试采 `通过` 或 `有条件通过` 后，无需管理员再次确认，可直接追加统一总底表。
2. 每次正式追加总底表后，即可开始 Obsidian 医生画像生成。
3. 本院 Obsidian 画像完成后，再进入下一家医院。

## 决策

1. 试采后存在两种可进入正式追加的门禁：
   - 管理员直接确认试采通过。
   - Claude 独立审计结论为 `通过` 或 `有条件通过`。
2. 当 Claude 已给出 `通过` 或 `有条件通过` 结论时，Codex 不再等待管理员二次确认，可直接执行正式追加。
3. Claude 结论为 `不通过` 时，Codex 不得正式追加，应记录为待人工处理或待新增专用适配器。
4. 正式追加后，Codex 必须先检查总底表、CSV 和更新报告，再执行 Obsidian 缺失画像补充生成。
5. Obsidian 画像生成默认使用不覆盖已有画像的缺失补充模式：
   `python .\work\generate_obsidian_profiles.py --generate-missing-only`
6. 画像生成后，Codex 必须核验本院 Markdown 数量和 `_索引.md` 链接数；核验完成后才进入下一家医院。
7. 不改变合规红线：仍只允许医院官网等官方公开渠道，禁止第三方平台、患者评价、隐私、登录或验证码绕过。
