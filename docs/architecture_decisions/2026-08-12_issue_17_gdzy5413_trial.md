## 阻塞、根因、解决方法与防复发

### 1. GitHub 404 输出类型导致错误判断

- 阻塞：前置门禁中 `gh api` 的 404 文本在 PowerShell 中以对象数组呈现，直接正则判断曾把预期的“远端分支不存在”误报为异常。
- 根因：把原生命令的多行标准错误当作单一字符串处理，没有先规范化输出类型。
- 解决：先 `Out-String` 或使用可明确取得 HTTP 状态的调用方式，再判断 404；没有据此执行任何越权远端写入。
- 防复发：GitHub API 错误判断必须同时校验退出码/HTTP 状态和字符串化正文，不对 PowerShell 对象数组直接做正则。

### 2. GitHub HTTPS fetch 多次超时并触发熔断

- 阻塞：创建 Issue 分支前，普通 GitHub HTTPS fetch 多次超时，无法证明分支基于最新 `origin/main`。
- 根因：本机到 GitHub Git HTTPS 的瞬时链路不稳定；不是业务代码、权限或分支内容错误。
- 解决：管理员解除熔断后，使用 `git -c http.version=HTTP/1.1 -c http.lowSpeedLimit=0 fetch --no-tags origin '+refs/heads/main:refs/remotes/origin/main'` 成功取得最新 main，再以 fast-forward 基线创建当前分支。
- 防复发：不得用手工拼接 GitHub API 提交替代“最新 origin/main”前置证明；传输失败时按有限次数停止，恢复后从身份和 main 引用重新核验。

### 3. bundled Python 缺少采集依赖

- 阻塞：bundled Python 本身没有 `requests`；系统 `python.exe` 只是 WindowsApps 占位符。
- 根因：解释器与第三方包分散在 Codex bundled runtime 和既有用户临时依赖目录。
- 解决：以 bundled Python 绝对路径运行，并通过 `PYTHONPATH` 复用既有临时 `requests/beautifulsoup4/openpyxl`；未安装或修改机器级依赖。
- 防复发：每个 Issue 开始先核验解释器绝对路径与依赖导入，不依赖 `python` 命令名，也不重复安装已存在的临时依赖。

### 4. 首次真实 TRIAL 只识别 20/21 个授权详情

- 阻塞：第一次真实 TRIAL 虽生成 10 位并满足科室门禁，但普查只识别 20 个唯一候选，低于只读现场已证明的 21 个，因此没有作为最终工件。
- 根因：`汪 何` 的姓名含官网排版空格，通用链接评分在站点专用 `.docnameall` 清洗前先做姓名校验并丢弃该卡片。
- 解决：GDZY5413 入口改为只枚举 `li.xinyutitle1` 内链接；只要 URL 满足严格 `specialist typeid` 即进入候选，再从 `.docnameall` 清除排版空格。第二次真实 TRIAL 恢复 37 个关系、21 个唯一详情。
- 防复发：专用站点应先使用结构与 URL 白名单确立候选，再做站点字段清洗；完整链路测试必须断言现场总数，不能只断言样本数。

### 5. 站点科室分区后缀被通用清洗器截断

- 阻塞：定向测试发现“针灸康复科五区”被通用科室规则截成“针灸康复科”。
- 根因：通用正则只保留 `科/中心` 结尾，没有覆盖该站点“科五区”结构。
- 解决：GDZY5413 站点级提取器保留官网匹配的完整科室原文；不扩大通用清洗器影响范围。
- 防复发：科室测试必须覆盖院内分区后缀；站点明确字段优先原样保留，通用截断只用于污染文本兜底。
