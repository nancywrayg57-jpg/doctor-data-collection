# 2026-08-09 官方医生画像采集流水线决策

## 背景

珠三角三甲医院医生画像项目只允许使用医院官网等官方公开渠道，禁止使用第三方平台、患者评价、私人联系方式、登录后数据或绕过验证码方式。管理员已经在官网入口台账中确认部分医院可采集。

## 决策

1. 台账是医院入口的单点来源，正式采集只读取 `入口台账` 中 `人工复核结果=确认可采集` 的医院。
2. 批量脚本按“通用主流程 + 单院适配器”实现。主流程负责读取台账、合规过滤、输出底表/报告；适配器只负责解析特定官网结构。
3. 第一轮脚本测试选择已确认A级医院 `南部战区空军医院`，原因是官网专家列表为公开静态分页，详情页包含明确的姓名、科室、职称、专业擅长字段。
4. 输出仍保持试点医院字段口径：姓名、医院、科室、职称、擅长、亮眼经历线索、来源链接、异常提示、复核状态等。
5. 官网未展示的信息保持空白或进入复核提示，不推断、不补造，不把“亮眼经历线索”直接写成对外宣传语。
6. 正式新增医生默认写入统一总底表 `珠三角三甲医院_医生画像自动采集总底表.xlsx`，不再为每家医院生成单独 Excel/CSV。底表内保留 `医院` 字段，并新增 `医院统计` 页说明每家医院的医生数、采集日期、待复核数和采集入口。
7. 统一总底表以已有 Excel 为可信来源。首次建表时从既有单院底表初始化；后续更新时优先保留总底表中的人工修正行，只追加新增医生，重复医生跳过。
8. `中山大学中山眼科中心` 已接入 `gzzoc_drupal_doctor` 适配器。该官网医生列表为 Drupal 专家介绍页，分页参数为 `page=0..17`，医生详情页为公开 `node/<id>` 页面；适配器从列表卡片提取姓名、职称、专业/科室、短简介，从详情页提取 `field-adept` 擅长和 `field-body` 简介。
9. 批量生成 Excel 默认不再生成预览图。原因是 `@oai/artifact-tool` 在预览渲染后偶发 Windows 进程退出码异常，但 Excel 输出内容已保存；主流程保留表格内容检查，预览图仅在人工需要视觉检查时单独触发。
10. 2026-08-10 起新增 `generic_official_template` 通用官网模板。该模板只跟随同一医院官网域名下的公开链接，自动识别分页、医生详情链接、详情页姓名/科室/职称/擅长/简介文本，并对低置信度记录写入复核提示。
11. 通用模板不是无复核全自动采集器。由于医院官网导航、新闻、采购公告和医生列表可能混在同一页面，通用模板全量追加总底表前必须先试采；脚本已设置安全阀，通用模板不带 `--allow-generic-append` 时不会写入统一总底表。
12. 管理员人工运行的推荐流程为：先 `--list-targets` 查看 A 级候选；对无专用适配器医院执行 `--trial-only --max-doctors 10 --no-xlsx` 小样本试采；人工复核姓名、科室、职称、擅长、来源链接质量通过后，再加 `--allow-generic-append` 全量追加。
13. 通用模板已用 `中山大学肿瘤防治中心` 官网入口完成 3 位医生试采验证，样本字段可正常抽取，且 `master_updated=false`；本次验证未向统一总底表追加测试数据。

## 关键文件

- `work/collect_official_doctors_batch.py`：读取台账、选择已确认A级医院、采集官网公开医生数据。
- `work/build_doctor_workbook.mjs`：将采集 JSON 生成正式 Excel 底表，支持单院底表与多院总底表。
- `医生画像仓库/99_资料来源/珠三角三甲医院官网入口台账.xlsx`：医院官网入口台账。
- `医生画像仓库/99_资料来源/珠三角三甲医院_医生画像自动采集总底表.xlsx`：正式追加使用的多院医生总底表。

## 扩展方式

新增医院时，先走 `generic_official_template` 小样本试采。通用模板质量通过的医院，可由管理员使用确认参数全量追加统一总底表；通用模板无法稳定识别的医院，再在主脚本中增加该官网的专用适配器识别和解析函数。官网适配器不是完全通用，通用的是读取台账、合规过滤、字段标准化、去重追加、总底表输出和报告生成。每家医院底表质量通过后，再接入 Obsidian 画像生成流程。
