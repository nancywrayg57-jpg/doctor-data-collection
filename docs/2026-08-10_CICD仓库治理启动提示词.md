1. 先审计、后提案、再授权、最后执行，禁止盲改仓库。
2. 信息不完整且无法从现场获取时，一次只问管理员一个决定性问题。

## 9. main Branch protection

日常 PR、审批、CODEOWNER 和 CI 门禁由 Branch protection 负责。对 `main` 配置：

- Require a pull request before merging
- Require at least 1 approval
- Dismiss stale approvals when new commits are pushed
- Require review from Code Owners
- Require approval of the most recent reviewable push
- Require status checks to pass
- Require branches to be up to date before merging
- Required check：真实 PR context `governance-check`
- Require conversation resolution before merging
- Require linear history
- Disable force pushes
- Disable deletions
- `enforce_admins=true`，owner 也必须走正常 PR、CI 和 CODEOWNER 门禁

本仓库属于个人账号仓库。使用 REST API 配置 Branch protection 时，如接口要求提交 restrictions，使用 `restrictions: null`；不要提交只适用于组织仓库的 user/team/app allowance 结构。遇到 `422 Only organization repositories can have users and team restrictions`，应修正 payload，而不是放宽权限。

## 10. main owner gate Ruleset

创建或修正 Ruleset：

- 名称：`main owner gate`
- Enforcement：`Active`
- Target：仅 `refs/heads/main`
- Bypass actor：仅 `nancywrayg57-jpg` 或经核验只包含该 owner 的 Repository admin
- 规则只保留：
  - Restrict deletions / `deletion`
  - Block force pushes / `non_fast_forward`
  - Require linear history / `required_linear_history`

明确禁止在日常治理模型中启用：

- Restrict updates
- REST ruleset 的 `update` rule
- `Write` 或 `Maintain` bypass
- `xtzhou247` bypass
- 不明确的团队、角色或应用 bypass

日常 PR 和 CI 门禁不要在 Ruleset 与 Branch protection 中重复维护。Ruleset 的职责是防止破坏性主分支操作；Branch protection 是日常合并门禁的单点来源。

## 11. 合并与阻塞诊断

owner 的常规合并命令为：

```powershell
gh pr merge <PR编号> --repo nancywrayg57-jpg/doctor-data-collection --squash --delete-branch
```

不得默认增加 `--admin`。普通 squash merge 被阻塞时，按顺序检查：

1. required status checks 是否成功。
2. 最新提交是否获得 CODEOWNER approval。
3. 是否有 unresolved conversations。
4. 分支是否落后并需要更新。
5. required check 名是否与真实 PR context 一致。
6. Ruleset 是否错误包含 `Restrict updates` / `update`。

若 Ruleset 的 `update` 导致 owner 也无法正常合并，永久修复是移除该规则，保留 deletion、non-fast-forward 和 linear history，再验证普通 squash merge；不得把 `--admin` 变成常规路径。

同一配置连续修复失败 2 次，停止写入并输出根因假设、GitHub 原始状态码/错误摘要、已尝试动作和下一步建议。同一治理分歧在 Agent 间协商超过 3 次，输出：

```text
[FATAL - HUMAN_INTERVENTION_REQUIRED]
```

等待管理员裁决。
